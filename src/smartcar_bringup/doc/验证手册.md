# smartcar_bringup 验证手册

本文档说明如何验证四轮麦克纳姆小车控制栈，覆盖 **WSL2 mock 仿真**（无硬件）
与 **树莓派实机** 两种场景。命令均可直接复制执行。

---

## 1. 前置：编译与环境

```bash
cd /mnt/d/Projects/smart_car_robot        # 树莓派上为 ~/smart_car_robot
colcon build --symlink-install
source install/setup.bash
```

- WSL2 开发机：跳过硬件，使用 `use_mock_hardware:=true`（默认）。
- 树莓派实机：需先把用户加入 `dialout` 组并确认串口设备名（见根目录 README §4.2）。

## 2. WSL2 mock 仿真验证:2026-08-08 验证通过

### 2.1 启动

```bash
ros2 launch smartcar_bringup smartcar.launch.py
# 等价于 use_mock_hardware:=true
```

启动后应在日志看到（先后两次 "Successfully switched controllers"）：

```
[controller_manager] Loaded hardware 'smartcar_system' from plugin 'mock_components/GenericSystem'
[spawner] Configured and activated joint_state_broadcaster
[spawner] Configured and activated mecanum_drive_controller
```

> 说明：`joint_state_broadcaster` 能激活，证明 8 个状态接口（4 关节 ×
> position/velocity）已注册可用；`mecanum_drive_controller` 能激活，
> 证明它成功 claim 了 4 个 velocity 命令接口。任一接口命名不符都会导致
> 控制器激活失败并报错。

### 2.2 查看控制器与接口（另开一个终端）

```bash
source install/setup.bash

# 两个控制器均应为 active
ros2 control list_controllers
# 期望：
#   joint_state_broadcaster    [.../JointStateBroadcaster]        active
#   mecanum_drive_controller   [.../MecanumDriveController]       active

# 8 个状态接口 + 4 个命令接口，均 available/claimed
ros2 control list_hardware_interfaces
# 期望命令接口（4）：
#   front_left_wheel_joint/velocity   [available] [claimed]
#   front_right_wheel_joint/velocity  [available] [claimed]
#   rear_left_wheel_joint/velocity    [available] [claimed]
#   rear_right_wheel_joint/velocity   [available] [claimed]
# 期望状态接口（8）：以上 4 关节各 position + velocity
```

### 2.3 里程计方向验证（前进 / 横移 / 旋转）

**关键提示**：Jazzy 的 `mecanum_drive_controller` 订阅的是
`geometry_msgs/msg/TwistStamped`（带时间戳），话题为
`/mecanum_drive_controller/reference`；而 `teleop_twist_keyboard` 默认发布
不带时间戳的 `Twist`。因此遥控必须加 `-p stamped:=true` 并 remap 话题。

#### 方式 A：键盘遥控

```bash
ros2 run teleop_twist_keyboard teleop_twist_keyboard \
  --ros-args -p stamped:=true \
  -r /cmd_vel:=/mecanum_drive_controller/reference
```

- `i` 前进 → `/mecanum_drive_controller/odometry` 的
  `twist.twist.linear.x` 为正。若启动 `use_ekf:=true`，
  `/odometry/filtered` 的 `pose.pose.position.x` 应增大。
- 麦轮横移键（`j`/`l` 在 holonomic 模式，先按 `b` 切换）→ `twist.linear.y` 变化。
- `k` 停。

#### 方式 B：命令行直接发布（可复制，便于自动化）

前进（+x）：
```bash
ros2 topic pub /mecanum_drive_controller/reference geometry_msgs/msg/TwistStamped \
  '{twist: {linear: {x: 0.3, y: 0.0, z: 0.0}, angular: {z: 0.0}}}' -r 10
```

横移（+y）：
```bash
ros2 topic pub /mecanum_drive_controller/reference geometry_msgs/msg/TwistStamped \
  '{twist: {linear: {x: 0.0, y: 0.3, z: 0.0}, angular: {z: 0.0}}}' -r 10
```

原地旋转（+z）：
```bash
ros2 topic pub /mecanum_drive_controller/reference geometry_msgs/msg/TwistStamped \
  '{twist: {linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {z: 0.8}}}' -r 10
```

另开终端观察里程计：
```bash
ros2 topic echo /mecanum_drive_controller/odometry
# 前进：twist.twist.linear.x  ≈ +0.3
# 横移：twist.twist.linear.y  ≈ +0.3
# 旋转：twist.twist.angular.z ≈ +0.8
```

查看 TF：
```bash
ros2 run tf2_tools view_frames
# 或
ros2 topic echo /tf
```

默认 `use_ekf:=false` 时，底盘控制器只发布
`/mecanum_drive_controller/odometry`，不会发布 `odom → base_footprint`
动态 TF。启用 `use_ekf:=true` 后，才应出现
`odom → base_footprint → base_link` 链路。

### 2.4 本仓库已验证结果（mock）

在 WSL2 + ROS 2 Jazzy 下用 rclpy 验证节点实测（2026-07-17）：

| 指令 | 期望 | 实测 `/mecanum_drive_controller/odometry` | 结论 |
|---|---|---|---|
| 前进 x=0.3 | linear.x > 0 | `vx = +0.3000` | PASS |
| 横移 y=0.3 | linear.y > 0 | `vy = +0.3000` | PASS |
| 旋转 z=0.8 | angular.z > 0 | `wz = +0.8000` | PASS |

> WSL2 沙箱下 mock 硬件为命令回环（`calculate_dynamics:=true`），
> 里程计忠实反映下发速度，方向与麦轮运动学一致。

## 3. 树莓派实机验证

### 3.1 启动

```bash
ros2 launch smartcar_bringup smartcar.launch.py \
  use_mock_hardware:=false serial_port:=/dev/ttyUSB0
```

- 无报错且三个控制器 active（含 `battery_state_broadcaster`）。
- 发布 `/mecanum_drive_controller/reference` 后电机按方向转动。
- 默认不启动 EKF；如需验证融合链路，启动时追加 `use_ekf:=true`，
  并检查 `/odometry/filtered` 与 `odom → base_footprint`。
- 首次上电需在实机标定：编码器倍频 `count_multiplier`、电机方向
  `direction_m1..4`、以及实测轮距回填 `controllers.yaml` 的
  `sum_of_robot_center_projection_on_X_Y_axis` 与 URDF 的
  `wheelbase`/`track_width`。



### 3.2 台架静态启动与 EKF 定位验证（2026-08-05）

> 安全前提：车辆放在台架上，四轮悬空；测试人员可以立即断开电机电源。台架测试只能验证轮速、里程计和融合链路的一致性，不能验证实际地面位移精度。

#### 3.2.1 启动与静止判据

```bash
source /opt/ros/jazzy/setup.bash
source install/setup.bash

ros2 launch smartcar_bringup smartcar.launch.py \
  use_mock_hardware:=false \
  serial_port:=/dev/ttyUSB0 \
  use_ekf:=true \
  use_camera:=false \
  use_joy:=false
```

另开一个终端，在不发送任何速度指令时采集原始与融合里程计：

```bash
source /opt/ros/jazzy/setup.bash
source install/setup.bash

ros2 topic echo /mecanum_drive_controller/odometry --once
ros2 topic echo /odometry/filtered --once
ros2 topic echo /imu/data_raw --once
```

静止时原始里程计的 `twist.twist.linear.x/y`、`twist.twist.angular.z` 应接近零。融合里程计的速度也应在 IMU 的噪声范围内接近零；若融合速度持续偏离零，先检查 `ekf_odom.yaml` 是否只融合 `yaw`，并确认没有在 IMU 未发布有效姿态时启用重力移除。

#### 3.2.2 MPU6050 静止标定

MPU6050 安装约定为右手系：`+x` 向前、`+y` 向左、`+z` 向上，芯片中心等同于车体坐标原点。标定时必须保持车辆和传感器静止且 `+z` 向上：

```bash
source /opt/ros/jazzy/setup.bash
source install/setup.bash

ros2 run ros2_mpu6050 ros2_mpu6050_calibrate
```

将输出的六个偏置写入单独的 `src/ros2_mpu6050/config/calibration.yaml`，不要改动默认 `params.yaml`。其中 `accel_z_offset` 已由标定工具扣除标准重力加速度 `9.80665 m/s²`；静止平放时不能直接把 `+z` 轴的加速度均值作为偏置，否则驱动会错误地消除重力。

重新启动后检查参数是否已覆盖默认配置：

```bash
ros2 param get /mpu6050_sensor gyro_z_offset
ros2 param get /mpu6050_sensor accel_z_offset
```

#### 3.2.3 台架受控运动

只执行一个方向，观察话题后先发送零速度，再进入下一个方向：

```bash
# 前进
ros2 topic pub --times 10 --rate 10 \
  /mecanum_drive_controller/reference geometry_msgs/msg/TwistStamped \
  "{twist: {linear: {x: 0.05, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}}"

# 停止
ros2 topic pub --once /mecanum_drive_controller/reference \
  geometry_msgs/msg/TwistStamped \
  "{twist: {linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}}"
```

前进时原始里程计的 `twist.twist.linear.x` 应为正；横移时 `linear.y` 的符号应符合坐标系；原地旋转时 `angular.z` 应为非零。停止后，原始和融合里程计速度都应回到接近零。依次将上面命令中的 `linear.x` 改为 `linear.y=0.05`，或改为 `angular.z=0.2`，即可完成横移和旋转验证。

### 3.3 断线容错测试

运行中拔掉 USB Type-C 串口线：

- 硬件接口 `read()` 检测到串口错误，连续 `max_read_misses`（默认 20）个
  周期无有效帧后返回 `ERROR`。
- controller_manager 记录错误并使硬件进入非活动状态，**进程不崩溃**。
- 重新插线并重启 launch 可恢复。

### 3.4 Web 遥测适配层验证（mock / 实机通用）

该适配层用于规避树莓派实机上 `rosbridge_websocket` 直接序列化
`nav_msgs/msg/Odometry` 时出现的
`cannot serialize type <class 'nav_msgs.msg._odometry.Odometry'>` 异常。
底盘原始话题 `/mecanum_drive_controller/odometry` 仍然保留，但只建议给 ROS
内部调试、录包与算法模块使用；网页侧应改订阅轻量话题 `/web/telemetry/*`。

启动 `smartcar.launch.py` 后，另开终端执行：

```bash
source install/setup.bash

# 1) 两个轻量遥测话题应存在
ros2 topic list | grep '/web/telemetry/'

# 2) 查看消息类型
ros2 topic type /web/telemetry/twist
ros2 topic type /web/telemetry/pose

# 3) 在底盘运动时应能收到消息
ros2 topic echo /web/telemetry/twist --once
ros2 topic echo /web/telemetry/pose --once
```

验证结果：


- [ ] `/web/telemetry/twist` 类型为 `geometry_msgs/msg/TwistStamped`。
- [ ] `/web/telemetry/pose` 类型为 `geometry_msgs/msg/PoseStamped`。
- 当小车前进、横移或旋转时，这两个话题会同步反映平面速度与二维位姿。
- `/mecanum_drive_controller/odometry` 继续可以用 `ros2 topic echo` 观察，说明
  ROS 内部原始里程计链路没有被删除。

网页侧验证要点：

- Web UI 连接 `rosbridge` 后，应订阅 `/web/telemetry/twist` 与
  `/web/telemetry/pose`。
- Web UI 不应再直接订阅 `/mecanum_drive_controller/odometry`。
- 浏览器连接后，`smartcar.launch.py` 所在终端不应再持续出现
  `rosbridge_websocket` 的 `cannot serialize type ... Odometry` 报错。

## 4. 摄像机推流验证

方案：**单实例 `ustreamer` + `camera_ustreamer_ctl`**（UVC 不能真双开；探测曾误报 `DUAL_OK`，第二路实际 `online=false`）。

### 4.1 依赖与设备

```bash
sudo apt install -y ustreamer
ustreamer --version
ls /dev/video*          # 期望存在 /dev/video0
groups | grep video     # 当前用户应在 video 组
```

### 4.2 随 bringup 启动（推荐）

```bash
ros2 launch smartcar_bringup smartcar.launch.py \
  use_mock_hardware:=false serial_port:=/dev/ttyUSB0
# use_camera 默认 true；仅当 use_mock_hardware:=false 且 use_camera:=true 时启动
```

启动日志中应出现 `camera_ustreamer_ctl`；另开终端：

```bash
# 健康检查
curl -s http://127.0.0.1:8082/health

# MJPEG 流头（应含 multipart 或 200）
curl -sI http://127.0.0.1:8080/stream | head

# 切到高清档，再确认流仍可用
curl -s 'http://127.0.0.1:8082/quality?mode=high'
curl -sI http://127.0.0.1:8080/stream | head

# 切回低延迟档
curl -s 'http://127.0.0.1:8082/quality?mode=low'
```

期望：

| 项 | 期望 |
| --- | --- |
| 推流端口 | `8080` → `/stream` |
| 控制端口 | `8082` → `/quality?mode=low\|high`、`/health` |
| 低延迟档 | 640×480@30，YUYV + CPU |
| 高清档 | 1280×720@15，YUYV + CPU |
| 关闭推流 | `use_camera:=false` 时无 `camera_ustreamer_ctl` / `ustreamer` 进程 |

从开发机（WSL2）验证局域网可达：

```bash
curl -sI http://192.168.10.17:8080/stream | head
```

上位机：打开 `http://localhost:3223` → 地图页切到「摄像机」→ 默认低延迟出图 → 点「高清」应短暂黑屏后出图。

### 4.3 关闭摄像机冒烟

```bash
ros2 launch smartcar_bringup smartcar.launch.py \
  use_mock_hardware:=false serial_port:=/dev/ttyUSB0 use_camera:=false
```

期望：底盘 / IMU / rosbridge `9090` 正常；无摄像机相关进程；控制与遥测不受影响。

### 4.4 独立启动摄像机（可选）

```bash
ros2 launch smartcar_bringup camera.launch.py
```

## 5. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 发布 `Twist` 无反应 | 控制器只收 `TwistStamped` | 用 `-p stamped:=true` + remap（见 §2.3） |
| 控制器一直 `inactive` | 接口命名不匹配 / URDF 未加载 | 检查 launch 日志中 hardware 加载与关节名 |
| WSL2 上服务查询卡住 | 默认 SHM 发现在 WSL2 不稳定 | 重启后台守护 `ros2 daemon stop`，清理 `/dev/shm/fastrtps_*` |
| 实机方向反了 | 电机接线镜像 | 改对应 `direction_mX` 为 -1 |
| `rviz2` 报 `could not connect to display` | SSH 无 X11 转发 / 无显示服务器 | ① Pi 接了显示器：`export DISPLAY=:0`；② SSH 转发：Windows 装 VcXsrv 后 `ssh -Y user@pi`；③ VNC：`sudo raspi-config` 开启 VNC，Windows 用 VNC Viewer 连接 |
| 摄像机无画面 / `:8080` 不通 | 未装 `ustreamer`、无 `/dev/video0`、mock 模式或 `use_camera:=false` | 见 §4；确认实机 `use_mock_hardware:=false` |
| 切档后黑屏较久 | 单实例重启 `ustreamer` 换分辨率 | 正常；若长期无流检查 `:8082/quality` 返回与 `/state` |
