# smartcar_bringup 验证手册

本文档说明如何验证四轮麦克纳姆小车控制栈，覆盖 **WSL2 mock 仿真**（无硬件）
与 **树莓派实机** 两种场景。命令均可直接复制执行。

---

## 1. 前置：编译与环境

```bash
cd /mnt/d/Projects/smart_car_robot        # 树莓派上为 ~/projects/smart_car_robot
colcon build --symlink-install
source install/setup.bash
```

- WSL2 开发机：跳过硬件，使用 `use_mock_hardware:=true`（默认）。
- 树莓派实机：需先把用户加入 `dialout` 组并确认串口设备名（见根目录 README §4.2）。

## 2. WSL2 mock 仿真验证

### 2.1 启动

```bash
ros2 launch smartcar_bringup smartcar.launch.py
# 等价于 use_mock_hardware:=true
```

启动后应在日志看到（先后两次 "Successfully switched controllers"）：

```
[controller_manager] Loaded hardware 'smartcar_system' from plugin 'mock_components/GenericSystem'
[spawner] Configured and activated joint_state_broadcaster
[spawner] Configured and activated mecanum_drive_controller
```

> 说明：`joint_state_broadcaster` 能激活，证明 8 个状态接口（4 关节 ×
> position/velocity）已注册可用；`mecanum_drive_controller` 能激活，
> 证明它成功 claim 了 4 个 velocity 命令接口。任一接口命名不符都会导致
> 控制器激活失败并报错。

### 2.2 查看控制器与接口（另开一个终端）

```bash
source install/setup.bash

# 两个控制器均应为 active
ros2 control list_controllers
# 期望：
#   joint_state_broadcaster    [.../JointStateBroadcaster]        active
#   mecanum_drive_controller   [.../MecanumDriveController]       active

# 8 个状态接口 + 4 个命令接口，均 available/claimed
ros2 control list_hardware_interfaces
# 期望命令接口（4）：
#   front_left_wheel_joint/velocity   [available] [claimed]
#   front_right_wheel_joint/velocity  [available] [claimed]
#   rear_left_wheel_joint/velocity    [available] [claimed]
#   rear_right_wheel_joint/velocity   [available] [claimed]
# 期望状态接口（8）：以上 4 关节各 position + velocity
```

### 2.3 里程计方向验证（前进 / 横移 / 旋转）

**关键提示**：Jazzy 的 `mecanum_drive_controller` 订阅的是
`geometry_msgs/msg/TwistStamped`（带时间戳），话题为
`/mecanum_drive_controller/reference`；而 `teleop_twist_keyboard` 默认发布
不带时间戳的 `Twist`。因此遥控必须加 `-p stamped:=true` 并 remap 话题。

#### 方式 A：键盘遥控

```bash
ros2 run teleop_twist_keyboard teleop_twist_keyboard \
  --ros-args -p stamped:=true \
  -r /cmd_vel:=/mecanum_drive_controller/reference
```

- `i` 前进 → `/odom` 的 `twist.linear.x` 为正，`pose.position.x` 增大。
- 麦轮横移键（`j`/`l` 在 holonomic 模式，先按 `b` 切换）→ `twist.linear.y` 变化。
- `k` 停。

#### 方式 B：命令行直接发布（可复制，便于自动化）

前进（+x）：
```bash
ros2 topic pub /mecanum_drive_controller/reference geometry_msgs/msg/TwistStamped \
  '{twist: {linear: {x: 0.3, y: 0.0, z: 0.0}, angular: {z: 0.0}}}' -r 10
```

横移（+y）：
```bash
ros2 topic pub /mecanum_drive_controller/reference geometry_msgs/msg/TwistStamped \
  '{twist: {linear: {x: 0.0, y: 0.3, z: 0.0}, angular: {z: 0.0}}}' -r 10
```

原地旋转（+z）：
```bash
ros2 topic pub /mecanum_drive_controller/reference geometry_msgs/msg/TwistStamped \
  '{twist: {linear: {x: 0.0, y: 0.0, z: 0.0}, angular: {z: 0.8}}}' -r 10
```

另开终端观察里程计：
```bash
ros2 topic echo /mecanum_drive_controller/odometry
# 前进：twist.twist.linear.x  ≈ +0.3
# 横移：twist.twist.linear.y  ≈ +0.3
# 旋转：twist.twist.angular.z ≈ +0.8
```

查看 TF（应有 odom → base_footprint → base_link）：
```bash
ros2 run tf2_tools view_frames
# 或
ros2 topic echo /tf
```

## 3. 树莓派实机验证

### 3.1 启动

```bash
ros2 launch smartcar_bringup smartcar.launch.py \
  use_mock_hardware:=false serial_port:=/dev/ttyUSB0
```

- 无报错且三个控制器 active（含 `battery_state_broadcaster`）。
- 发布 `/mecanum_drive_controller/reference` 后电机按方向转动。
- 首次上电需在实机标定：编码器倍频 `count_multiplier`、电机方向
  `direction_m1..4`、以及实测轮距回填 `controllers.yaml` 的
  `sum_of_robot_center_projection_on_X_Y_axis` 与 URDF 的
  `wheelbase`/`track_width`。

### 3.2 运动方向复现记录（2026-07-19）

接线约定（实车）：`M1` 右前、`M2` 左前、`M3` 右后、`M4` 左后。

通过 ros-mcp-server 向 `/mecanum_drive_controller/reference` 持续发布
`TwistStamped{linear.x=0.1}`（约 10 Hz）：

| 轮位 | 关节名 | 驱动板 | `/joint_states` velocity 符号 | 台架物理转向（修复前） |
|---|---|---|---|---|
| 左前 | `front_left_wheel_joint` | M2 | +（约 +2.4 rad/s） | 向后 |
| 右前 | `front_right_wheel_joint` | M1 | +（约 +2.4 rad/s） | 向前 |
| 右后 | `rear_right_wheel_joint` | M3 | +（约 +2.4 rad/s） | 向后 |
| 左后 | `rear_left_wheel_joint` | M4 | +（约 +2.4~4.8 rad/s） | 向前 |

结论：

- 软件侧四轮同号，麦轮逆解正常。
- 物理现象与「左前向后、右前向前、右后向后、左后向前」一致。
- 根因：M2 / M3 电机极性与关节正向约定相反。
- 修复：`direction_m2=-1`、`direction_m3=-1`（见 `smartcar.ros2_control.xacro`）。

### 3.3 台架悬空单轮偏速与 Y 轴偏移分析（通俗易懂版）

#### 现象描述与疑问
在实机台架测试中，使用命令行持续下发纯前进指令：
```bash
ros2 topic pub /mecanum_drive_controller/reference geometry_msgs/msg/TwistStamped \
  '{twist: {linear: {x: 0.1, y: 0.0, z: 0.0}, angular: {z: 0.0}}}' -r 10
```
将小车悬空放置，观察里程计输出与轮速反馈图表，发现：
- **`position.x` 正常增大**（小车往前走）；
- **`position.y` 却不断减小变负**（里程计显示小车在向右侧漂移）。

---

#### 🚗 10 岁小朋友都能看懂的原因解释

##### ① 用“4 匹马拉车”打个比方
想象小车是由 **4 匹聪明的小马** 组装在一起拖着跑的玩具车：
- 🐴 **左前马 (FL)**：对应 `/joint_states/velocity[0]`
- 🐴 **右前马 (FR)**：对应 `/joint_states/velocity[1]`
- 🐴 **左后马 (RL)**：对应 `/joint_states/velocity[2]`
- 🐴 **右后马 (RR)**：对应 `/joint_states/velocity[3]`

小车装的是特殊的**麦克纳姆轮**（上面有斜着 45 度的斜纹小辊子）。
这种轮子有个神奇特性：**如果左后马 (RL) 跑得太快，不仅会把车往前推，还会产生向右侧侧滑的分力！**

##### ② 看数据找“捣蛋鬼”
当我们对小车喊：“**小车小车，用每秒 0.1 米的速度直直往前走！**”
看电脑记录的四匹马实际跑的速度（`joint_states/velocity`）：
- 🐴 **左前马 (FL - `velocity[0]`)**：每秒跑 **12.3 圈**（很听话）
- 🐴 **右前马 (FR - `velocity[1]`)**：每秒跑 **12.3 圈**（很听话）
- 🐴 **左后马 (RL - `velocity[2]`)**：每秒跑 **14.5 圈**（**捣蛋鬼！它兴奋过度跑得太快了，多跑了约 18%！**）
- 🐴 **右后马 (RR - `velocity[3]`)**：每秒跑 **12.3 圈**（很听话）

##### ③ 为什么 `position.x` 变大，而 `position.y` 不断变小？
- **为什么 `position.x` 变大？**  
  因为 4 匹马都在向前跑，所以小车一直在往前推进，前向距离 $X$ 越来越远（增大）。
- **为什么 `position.y` 不断变小（向右偏）？**  
  因为**左后马 (RL)** 跑得太快了（14.5 > 12.3）！它的斜向推力打乱了平衡，把整个车身往右后方一直推。电脑根据四个轮子速度算账（里程计数）时，算出小车每秒都在往右滑一点点，所以右向位置 $Y$ 就变成了负数，距离越远偏得越多！

---

#### 🛠️ 应该如何解决？（清晰可执行的方案）

1. **第一步：给左后马“降降温”（驱动板电机速度闭环 PID 调优）**
   - **原因**：电机驱动板在空载时发出的控制功率一致，但由于电机制造公差或驱动板 PID 没调好，导致左后电机“抢跑”。
   - **做法**：重新调节驱动板内的电机 PID 闭环参数，使驱动板能自动将左后电机的空载转速压回到和其他三轮一致的 12.3 rad/s。

2. **第二步：在软件里加一个“限速调节器”（Scale 速度系数补偿）**
   - **做法**：若暂时不方便修改驱动板固件，可在硬件接口层 `MecanumSystemHardware` 或配置中，单独给左后轮（`rear_left_wheel_joint`）乘以一个约 `0.85` 的缩小系数（$12.3 / 14.5 \approx 0.85$），把发给左后电机的指令调小，平衡四轮速度。

3. **第三步：给小车装上“指南针”（IMU 姿态传感器 EKF 融合）**
   - **做法**：接入现有的 MPU6050 IMU 传感器，使用 `robot_localization` 扩展卡尔曼滤波（EKF）融合姿态角（Yaw），实时修正偏航，防止 $Y$ 轴累计漂移。

### 3.4 断线容错测试

运行中拔掉 USB Type-C 串口线：

- 硬件接口 `read()` 检测到串口错误，连续 `max_read_misses`（默认 20）个
  周期无有效帧后返回 `ERROR`。
- controller_manager 记录错误并使硬件进入非活动状态，**进程不崩溃**。
- 重新插线并重启 launch 可恢复。

## 4. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 发布 `Twist` 无反应 | 控制器只收 `TwistStamped` | 用 `-p stamped:=true` + remap（见 §2.3） |
| 控制器一直 `inactive` | 接口命名不匹配 / URDF 未加载 | 检查 launch 日志中 hardware 加载与关节名 |
| WSL2 上服务查询卡住 | 默认 SHM 发现在 WSL2 不稳定 | 重启后台守护 `ros2 daemon stop`，清理 `/dev/shm/fastrtps_*` |
| 实机方向反了 | 电机接线镜像 | 改对应 `direction_mX` 为 -1 |
| `rviz2` 报 `could not connect to display` | SSH 无 X11 转发 / 无显示服务器 | ① Pi 接了显示器：`export DISPLAY=:0`；② SSH 转发：Windows 装 VcXsrv 后 `ssh -Y user@pi`；③ VNC：`sudo raspi-config` 开启 VNC，Windows 用 VNC Viewer 连接 |
